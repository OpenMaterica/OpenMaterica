# Scripts

Development and CI tools; nothing in the package imports them. All but `gen_shapes.py` use Python's standard
library only (`measure.py` at import: its pytest plugin imports pytest), so the sign-off check runs before any
dependency is installed.

| Script | What it does | When CI runs it |
|---|---|---|
| `check_anomalies.py [REGISTRY] [--pyproject PYPROJECT]` | checks the known-anomalies registry (`docs/validation/known_anomalies.yaml`) against MADDENING's record schema, standing in for MADDENING's validator (the registry's header says why): the top-level fields and no other, `materica_version` in place of `maddening_version` and equal to the package's version in `pyproject.toml`, `generated_date` a date; in each entry MADDENING's required fields and no field outside its record, the `OMAT-ANO-` prefix and three digits, each identifier once, the severity, safety relevance and resolution status among their values, `affected_versions` a PEP 440 version specifier set or `none`, and each affected component `schema:`, `reader:`, `method:`, `model:` or `data:` and a name. It reads the YAML as a subset, as PyYAML reads it, and refuses the rest, an unquoted number or date and a key given twice among it, at its line. Standard library only | on every run of CI, in the first job, whatever the change touches |
| `check_claims.py check [BASE] [--head REV] [--description FILE] [--facts FILE] [--rulings FILE] [--figures-advisory]`, `check_claims.py record VALUE WHAT --how HOW [--at REV] [--facts FILE]`, `check_claims.py baseline [--at REV]` | checks what a branch claims against what shows it, from the merge base of `BASE` (`origin/main`) to the head, read from git (CONTRIBUTING, "Before asking for review"). Git facts, in the pull request's description (a file) and the branch's commit messages: each commit name names one commit, on the branch or on `BASE`, unless its sentence names a pull request (`#N`); one called the head or the base is that commit; and a count of the branch's commits, files changed (a rename one file, as git counts it) or lines added and removed, in the forms the merged descriptions use (the module's docstring lists them), is git's. Figures, in the description and the CHANGELOG lines the branch adds (a line moved whole is not added): each number that is no git fact and of no kind that is no measurement (a numbered thing, a version, a flag, an identifier, a date, a value in a physical unit, a confidence level, code, a link, a quotation) matches a fact in the facts file (by default `claims-facts.json` in the worktree's git directory, never committed, so a check run elsewhere names it with `--facts`: its value, the words after it, how it was measured and at which commit), or is marked an estimate (`about`, `roughly`, `~`, `estimated` and the like just before it, `estimate` after it in its phrase); a fact measured before the head holds only where the commits since change prose Markdown alone (the CHANGELOG, a README, the documentation, but not the specification or a file a test reads by the readers `pre_review.py` declares; a moved file by both its names), and the check prints them; `record` adds a fact. A CHANGELOG figure that `claims_baseline.json` holds, by its three words either side, was in the CHANGELOG at the baseline's commit on `main` (each entry with its reason, real or not) and is counted, not reported, while the CHANGELOG holds it no more often than then; the check refuses a baseline entry that is no figure there, so the baseline can only shrink, and `baseline` writes it; only `--figures-advisory` turns the figure check's failing off (the CHANGELOG's part too), printing each finding as `advisory figure finding:` and leaving the git facts and the ruled wording to fail, as CI's pull-request job runs it. Ruled wording, given the rulings file, the maintainer's private file whose path is given at run time and of which nothing is printed but the words compared (its markup, the maintainer's attribution and question labels left out): where a run of six words or more of a ruling and of a specification sentence the branch adds nearly match, they match word for word, and a difference prints both; a line of its own `accepted wording: "..."` just under a ruling names a wording of that ruling landed otherwise on purpose, whose difference is printed apart, not reported. Prose claims, counts written in words, a ruling paraphrased past near and the forms the docstring names as unread are the reviewer's. Standard library only | on every pull request, on every push and edit of its description, in `claims.yml` (`.github/workflows/README.md`, "Claims"): the git facts fail the job, the figures are advice (`--figures-advisory`), and no rulings file is given; a builder runs it before asking for review, with the rulings, and again before the pull request leaves draft |
| `check_confidential.py [--key-file KEY] [--messages RANGE \| --pre-push REMOTE] [--ref-name NAME]` | checks that no tracked file, and no message of a commit in `RANGE`, names one of the maintainer's private projects or carries a private path (CONTRIBUTING, "Confidentiality"); the names by their HMAC-SHA256 in `confidential_digests.txt`, under a key from `CONFIDENTIAL_SCAN_KEY` or `--key-file`, and the paths without a key. A finding gives a term's first letter and length, never the term. A binary file, or text in UTF-16 or UTF-32, is read by its printable runs of four ASCII characters or more; what a file holds compressed is not read. `--pre-push`, from git's pre-push input on standard input, checks what a push to `REMOTE` publishes instead: the name of each ref it writes, each file content and annotated tag the remote lacks by what it advertises now (`git ls-remote`), at each path it has, and each commit's message. `--ref-name` checks a ref's name too. `--digest` writes the digest file from terms on standard input | on every pull request and push, in the first job, whatever the change touches, with the messages the event brings and a pull request's branch name; without the secret, the paths only, with a warning |
| `pre-push` | git's pre-push hook, not run by CI: `check_confidential.py --pre-push` with the push's remote and refs, and `--key-file` from `git config openmaterica.scanKeyFile` where set (`~` expanded), or `CONFIDENTIAL_SCAN_KEY`; refuses the push on a finding, and without a key unless `git config openmaterica.scanWithoutKey true` says the clone has none (the paths alone). Installed by hand (CONTRIBUTING, "Confidentiality") | never: CI's own scan runs in the first job |
| `check_signoff.py <base> <head>` | checks that every commit in `base..head` carries a DCO `Signed-off-by` from its author (CONTRIBUTING constraint 1); the design commits made before the first code commit are exempt, by ancestry of one pinned commit | on every pull request, in the first job, whatever the change touches |
| `check_site.py <staged site> [--readme README.md]` | checks a copy of the site as the Pages workflow stages it: it holds no symbolic link and no hidden path, which the Pages artifact would publish dereferenced or leave out; in every page (`*.html`, `*.htm`, `*.xhtml`), each local link, image and icon, and each icon of the web manifest, resolves to a file of the copy (a directory to its `index.html`, a fragment to an anchor); each page has one content security policy in its head as a browser reads it, before anything it loads or any style, that gives no directive twice, whose default is `'none'` and whose sources are on a closed list (`'none'`, `'self'`, `'unsafe-inline'`, hashes, nonces, `data:`); nothing loads from elsewhere (an image, an icon, a script, a style, a frame, an SVG image or use, a `background`, a style's `url()` or `@import`, in the page or a stylesheet of the copy it loads, whose local addresses resolve too); no page has a `<base>`; and each image of the README, inline, as HTML or by a reference, by a path or a URL into this repository, names a file of the tree. Standard library only | in the site job, on the copy its staging step writes, on every change but one to documentation alone |
| `check_wheel.py <wheel>` | checks that the built wheel holds `py.typed`, every file under `data/` and `schema/` byte for byte and no other there, the licence as an SPDX expression with its file (PEP 639), no run-time dependency, and nothing outside the package | in the static job, after `uv build`, when a change touches code |
| `freeze_schema.py <MAJOR.MINOR> \| --check` | at a release, adds the schema version to `tests/spec_sync/released_schemas.json`, with every file under `src/materica/schema/<version>/` and the SHA-256 of its bytes; refuses a version whose `$id`s are not their paths, and never rewrites one already there. `--check` writes nothing and fails where a released version's file was added, removed or changed, an `$id` is not its path, or its directory is gone (CONTRIBUTING, "Release gate"); it refuses a `-dev` directory, which the release renames first (`src/materica/schema/README.md`, "The next line") | not as a step of its own: `tests/spec_sync/test_released_schemas.py` runs the same check in the tests job |
| `gen_vocabulary.py [--check]` | generates `src/materica/schema/0.1/vocabulary/*.json`, each with its `$id`, from the specification's tables and the token lists in its cells and sentences: reasons with the steps that give them, fields, conditions, specimen facts, acceptance kinds, the forms' tokens and the element symbols, statistics and uncertainty tokens, provenance tokens and result labels; the pattern of an identifier a fact's row writes (`"UBERON:<digits>"`); and the bindings the writer schema applies, each section's field names and each field's forms, bases, unit and label, the fields an overlay may replace, and each numeric condition's unit; a list of tokens is read in full, and a cell or list it cannot read, a name listed twice in one table, or a row a binding cannot state, stops it | with `--check`, in the generated-files job, when a change touches code |
| `gen_reader_schema.py [--check]` | generates `schema/0.1/record.reader.json` from the writer schema, opened where `record_format.md` section 1 item 2 says a reader is open, with the shapes of a value field and a section's `specimen` in `$defs`, as step 8 checks them: without the members marked `x-materica-write-only`, a member marked write-only `unless` a condition checked under that condition alone, and without the vocabulary's bindings, which bind a field to its row and which a read checks in its own steps; it refuses a writer schema it cannot open faithfully, such as anything it opens under `if` or `not`, there or through a `$ref`, or a keyword it does not know | as above |
| `gen_shapes.py [--check]` | generates `src/materica/shapes.py` and `shapes.pyi`, the JSON shapes as TypedDicts, from the writer schema, `case.json` and the read request and result, the declaration and the build's report, with datamodel-code-generator and ruff (pinned in the dev group), working in a temporary copy of the schemas in which every `integer` is a `number`, since the reader gives every number as a double, and the vocabulary's bindings, the declaration's rules and bindings and the read request's acceptance shapes it applies are left out, since a TypedDict cannot narrow a member by the name it sits under; runs on Python 3.11 to 3.14, since the generator does not run on 3.15 | as above |
| `gen_kill_counts.py [--check \| --record REPORT ... [--group GROUP ...] \| --against REPORT ... \| --measure [--record] [--workers N]]` | writes the kill counts of `tests/property/README.md` from `tests/property/kill_points.json`, which holds every mutant search's kill point at the small and the original size (one group per test function and one line per mutant, under `kills`) and what those depend on (under `inputs`: the Hypothesis version `uv.lock` pins, and a digest of the source of each `kill` helper that runs a search and of `MUTANT_SEARCH`, since Hypothesis seeds a derandomised search from its function's source, so that an edit to a helper moves hundreds of kills at once), in the one layout the script writes: the last cell of each row of a table under a comment that names its group (`<!-- kill points of every search of <file>::<function> (scripts/gen_kill_counts.py) -->`, or `of some searches of`), and the summary between its two comments. `--check` writes nothing and fails where a count differs, the file is not in its layout, an input differs from the tree's (naming which, and that the cure is to record again), a recorded group has no table (but the two in `NO_TABLE`), a table of every search lacks a recorded mutant's row, a row names a mutant twice or a table a group the file does not hold, or a kill point lies after the 500th example (the margin guard, naming each); a row of a mutant the file does not hold yet passes it. `--record` reads `examples_to_kill` from JUnit reports pytest wrote and records them where they cover every recorded group, each of its recorded mutants at both sizes, and is refused otherwise, naming each group they lack, whose kill points recording would drop; `--group GROUP` records the named groups alone, which the reports must cover, and keeps the others (refused where the inputs changed); a mutant or group that is gone is dropped by `--measure --record` alone; `--record` is refused where a mutant search passed without recording its kill; `--against` holds the file to a run of every search and fails where an input differs (first, and where Hypothesis is installed in another version), a report's kill differs from the recorded one, a search it ran is not recorded, a recorded search of a group it holds has no kill in it, a README row of such a group names a search it did not run, a recorded group is missing from the run, or a mutant search passed without recording its kill (`--partial` excuses the missing groups, for a hand-run report); `--measure` runs every mutant search (`pytest tests/property --property-controls only`) into a temporary report and checks it so, or records it with `--record` (the file then holding exactly that run's groups), and needs the project's environment. A search's kill does not depend on the profile or the Python, so a local run records CI's. Standard library only | with `--check`, in the generated-files job and the per-commit job, when a change touches code; with `--against`, in the `kill_points` job, on the reports of all of a Python's `controls` parts together |
| `repeat_runs.py request \| seeds \| derandomized \| record SEED STATUS REPORT \| summary DIRECTORY` | the repeat workflow's checks and sums (`.github/workflows/repeat.yml`). `request` checks a dispatch's inputs, read from the environment, and writes them as the step's outputs: it refuses a node that is not a file or directory under `tests/` (by a path of plain parts, never `..`, and inside `tests/` once resolved), a profile or a Python not listed, a count or a first seed out of its bounds or not in plain digits, a character other than printable ASCII, and any extra argument but `--shard` and `--property-controls`, each once, giving every reason; `seeds` lists one job's seeds, no two runs of a request sharing one; `derandomized` reads the node ids pytest collected and warns once, never refuses, where any lies in a module whose searches are derandomized (one `PROPERTY_CONTROLS` selects, or whose code sets `derandomize` to anything but off, fixes a seed with `@seed`, or runs `MUTANT_SEARCH` or `examples_to_kill` by any name), whose every repeat draws the same examples, naming the modules but for the whole suite (`NODE`); `record` writes one run's record, a line of JSON, from pytest's exit status and JUnit report, with each failing example Hypothesis reported; `summary` sums every job's records in the step summary (the runs, the failures with their seeds and examples, and the failure rate with its one-sided 95 % upper bound) and fails where a run failed or did not finish, a seed has no record or two, a job of runs did not succeed, or the run's attempt (`ATTEMPT`) is not its first; of a seed's two records, as from a job run again, it counts the one that did not pass. Standard library only | never on a push or a pull request: in the repeat workflow, which runs only when dispatched by hand (`tests/README.md`, "Repeat runs on CI") |
| `pre_review.py [BASE] [--list] [--stage fast\|tests\|properties\|whole] [--workers N] [--keep-going] [--key-file KEY]` | the builder's check before asking for review (CONTRIBUTING, "Before asking for review"): finds the files changed from the merge base of `BASE` (`origin/main`) and `HEAD` to the working tree, with the untracked, and runs the checks that apply, printing each with the paths that selected it. Every change: the sign-off and confidential scans, every generator's `--check` on Python 3.11 in an environment of its own, and `freeze_schema.py --check`; a change to code, as CI's gate reads it: ruff, `ruff format --check`, mypy and pyright, then the static job's wheel steps (`uv build`, `check_wheel.py` and the consumer snippet's mypy and pyright against the installed wheel, in a temporary directory; `--wheel-check` runs them alone); a changed Python file: the test files that import it, directly or through others, those of `tests/property` as their whole shard at the `ci` profile (and, where a shard holds mutant searches or the recorded kill points or their README changed, `gen_kill_counts.py --measure`), and the few tests that read the whole tree instead of importing it (`TREE_READERS`); a changed specification, schema, conformance, spec-sync table, workflow or build file: the tests that hold it or open it (`DATA_RULES`), and the shards of the modules that read it. A change it cannot map to a test (a Python file no test imports, a file under `tests/` in no group of tests, a conftest of a directory that is none) selects the whole of `tests/unit` and says why. A stage that fails stops the run before the next unless `--keep-going`. The stage `whole`, run only when asked for, runs every test under `tests/` but those `LEFT_TO_CI` names, each with why (the property modules, which CI's shards run), its selection the tree's own. It ends with reminders for what no check decides: code beside a CHANGELOG that was not, and each count the branch's CHANGELOG lines and commit messages state, to recount. Every `uv run` it plans is `--locked` and `uv lock --check` comes first, so a lock file out of date is refused, never rewritten. A name in a diff is printed with its control characters escaped and a command quoted so that it pastes back as the same arguments; a file that is no regular file is not opened, and one that is not UTF-8 is named and sends its change to the whole of `tests/unit`. It runs what applies, never all that CI runs (not the site job, the fuzz job or the wheel check's two controls), and replaces none of it. Standard library only | never: a builder's tool |
| `input_coverage.py list \| run \| check (NAME \| --tests ARG ... --sites PATTERN ...) [--report REPORT] [--parallel K] [--workers N] [--budget SECONDS] [--root TREE]` | whether the tests hold every draw (`tests/property/README.md`, "Every draw is held"): runs a selection of tests (a name in `tests/property/input_coverage_baseline.json`, or the pytest arguments given) once with the plugin `tests/property/input_coverage.py`, derandomized at `ci`, recording each site its patterns take (`fnmatch` on its name; one beginning with `!` leaves out what it matches, and the last that matches decides), then each cut of those sites (each value or option dropped in turn, each bounded end of a range pinned and kept off, a collection held to and kept off its least and its greatest size, a permutation held to the order given) as a pytest process of its own, `K` at a time, stopping at the first failure; records each cut `held` (with the test and its message), `not held`, `invalid`, `empty`, `not applied` or `error`, and lists the draws it cannot cut. `check` (and `run` once every cut has run) fails on a cut not held, or an uncut draw, that the baseline does not list, and on a baseline entry now held or no longer made, so that an entry cannot outlive its gap. `--budget` stops starting cuts after that many seconds (exit 2); a later run with the same report goes on. Standard library only | not yet: a builder's tool, run locally under the heavy-run lock, until CI's measurement matrix runs it |
| `mutant_runs.py request \| run DIRECTORY \| imports [PATH ...] \| table DIRECTORY OUTPUT` | the mutant workflow's checks, runs and table (`.github/workflows/mutants.yml`). `request` checks a dispatch's inputs, read from the environment, and every patch they name, and writes them as the step's outputs, the matrix of jobs among them (the baseline, `""`, and each mutant): a patch must be `mutants/<name>.patch`, a regular file committed at the dispatched commit, named by 1 to 64 letters, digits, `_` and `-`, at most 1 MiB of UTF-8 text with no control character but tab and line feed, that git reads as a patch in its own format, each file's `diff --git`, `---` and `+++` lines naming its one path, with no binary data, rename, copy, link or submodule, touching only plain paths inside the checkout, none inside `.git`, under `.github/` or `mutants/`, none git ignores, nor the runner, `pyproject.toml`, `uv.lock`, `uv.toml`, `.python-version` or `.python-versions`; `verdict` alone makes one: broken where the patch did not apply or the code did not import or collect, in one process or under pytest-xdist (what the report names beside the collected tests, `uncollected`), whatever else the record holds, survived, killed (with the collected test that failed first) or undecided. `imports` compiles each Python file it is given and imports every module of the package from the checkout. `table` writes one row for the baseline and each mutant to the step summary and to `table.md` and `table.json`, with the paths its patch touches, marking a kill by a patch that edits the tests or pytest's settings, and the line that replays a row with the dispatch's selection and seed, and fails unless the baseline passed and every mutant was killed, each with one record, the mutants' jobs succeeded and the run is on its first attempt. | `measure.py floors\|drift\|regions\|fuzz SELECTION ... \| request \| matrix \| job DIRECTORY \| summary DIRECTORY OUTPUT \| report PATH ... \| fetch RUN` | the measurements a property piece makes before review, run alike here and in `.github/workflows/measure.yml`'s jobs (`tests/README.md`, "Measurements on CI"): `floors`, each property function over derandomised streams at `ci`, each feature's shares, variance ratio and each floor's false failure at the audits' model and at the variance measured (flagged above 1e-6); `drift`, each mutant search's kill over streams, stream 0 against `kill_points.json`, a kill from the 400th example or past the 500th; `regions`, each feature's mean share at the head against a base's, exported into an environment of its own (flagged below 0.8), and every search's kill at the head against both records; `fuzz`, a control of `ci.yml`'s step run as the step runs it, its rate and the miss of a pair and of CI's runs. A generator writes its files; with `--check` it writes nothing and fails where a file on disk differs from what
its source gives, so a hand edit to a generated file, or a source edited without regenerating, fails CI
(CONTRIBUTING, "Changing the schema"). Each script has tests in `tests/unit/` that show it failing on what it
must refuse.
